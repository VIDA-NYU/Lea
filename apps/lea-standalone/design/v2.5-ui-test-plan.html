T1 Does the agent use the MCP tools once the skill is scoped? ~5 min

The one open question in the whole phase. Your first run had MCP resolved, the server warm, 23 tools registered — and the model used search_mathlib and suggest_imports instead, never inspecting a goal. The skill was scoped to nothing, so its own instruction ("lean_goal — MOST IMPORTANT tool, use often!") never reached the prompt. This re-runs the same proof with that instruction present. It decides whether a skill+server pack works, or whether the recommended-tool-subset is needed instead.
  1. Confirm housekeeping #2 is done (the skill is on All projects).
  2. Open a session inside the PDE project — it is the one with lean-lsp scoped.
  3. Paste:
Prove that the derivative of fun x : ℝ => x^2 is fun x => 2*x.
Hoped for: tool steps named lean_goal, lean_hover_info or lean_multi_attempt — the agent inspecting real proof state rather than guessing lemma names. Also watch for a read_file on something under references/: that is the progressive-disclosure half (T2) proving itself in the same run.
If it again only uses search_mathlib: that is a real finding, not a failure of the test — it means prompt guidance is not enough and the answer is the recommended tool subset (already built, catalog entry lean-lsp). Tell me and I will switch the resolution to use it. Also worth noting: if it uses both search_mathlib and lean_leansearch for the same lookup, that is the overlap problem costing you budget twice.

T3 Project → Skills / MCP tab ~2 min

The project tier of the two-tier model. Ticking here applies to every session in the project, and the global row is deliberately shown on-and-locked — un-ticking it would silently mean "stop being global", a Library-level decision.
  1. Open the Real Analysis project → Skills / MCP tab.
  2. Tick lean-lsp under MCP servers.
  3. Reload the page and return to the tab.
  4. Untick it again.
The tick survives the reload. The lean4 skill row shows as on with an "All projects" badge and its checkbox disabled.
If the locked global row reads as broken rather than inherited, that is a copy problem worth telling me about — it is the one piece of this UI I expect to be misread.

T4 Add a sub-agent through the guided form ~4 min

This is where the four authoring questions do real work: "When should Lea use this?" becomes the line the coordinator reads when choosing whom to delegate to. Writing it well and making delegation work are the same act.
  1. Library → Sub-agents → Add a sub-agent.
  2. Name: Counterexample hunter. Then answer the four questions, e.g.
    · What is it? — A helper that looks for a counterexample before committing to a proof.
    · When should Lea use this? — When a statement looks false, or a proof attempt has failed the same way twice.
    · When should Lea NOT? — When the statement is routine or already close to compiling.
    · How? — Try small cases first: n = 0, n = 1, the empty set, the zero function.
  3. Add it, then open one of the four imported roles (e.g. proof-golfer) and check it offers Delete; open a built-in (premise-search) and check it offers Reset to defaults instead.
The new role appears in the list tagged yours. Built-ins can be retuned but not deleted; imported and hand-written roles can be deleted.
If the four questions read as vague or you would not know what to type, say so — that copy was written blind and is the single least-validated thing in v2.5.

T6 Add a custom HTTP tool ~4 min

A REST endpoint as a tool, no code and no install. The example below is real, public, and needs no API key — I verified it returns live data before writing this.

  2. Name: Paper search. Web address:
https://api.crossref.org/works?query.bibliographic={query}&rows=3&select=title,DOI
  1. Values Lea fills in: query
  2. Leave the API-key box empty. Answer the four questions (e.g. "Finds published papers by title or topic" / "When the user asks whether something has been published, or for a reference" / "Not for looking up Lean lemmas — use Mathlib search for that").
  3. Scope it to All projects, then ask in any session: Find me papers about the Erdős discrepancy problem.
A paper-search tool step, and real paper titles in the reply.
Also try the guard: attempt to save a tool pointing at https://localhost:8001/api/settings — it must be refused at save. That is Lea's own API; a tool able to reach it could read your settings.

T7 The missing-key warning and the clear guard ~3 min

  2. Return to the MCP servers page.
  3. Now go to Settings → API keys, add WOLFRAM_API_KEY with any dummy value, save, then try to clear it.
  4. Undo: remove the key name from the server.
Step 2: an amber banner naming WOLFRAM_API_KEY and which server needs it. Step 3: clearing is refused, naming the server that still uses it.

  1. Walk the four Library pages and the Project → Skills / MCP tab, reading only the labels and hints.
  2. Flag anything you would not be able to answer without asking me.
